# 飞控台架测试手册 V0.3（X-MAV AP-H743v3）

目的：底盘和 VCU 还没到位时，只用 X-MAV AP-H743v3 飞控（加少量辅助设备）验证：固件、Lua 脚本、CAN 通信、解锁拦截、RTK 检查、导航输出的 v/ω。
调试软件：**Mission Planner（MP）稳定版**，以下简称 MP。本手册按"第一次用 MP"来写。

> MP 各版本的中文翻译略有不同，菜单名后面的括号里附了英文原文，找不到时可以对照英文。

## 0. 准备

### 0.1 测试分级与所需设备

| 级别 | 需要的设备 | 能验证的内容 |
|---|---|---|
| A | AP-H743v3 飞控 + USB 数据线 + **microSD 卡**（首次刷机可能还要 STM32CubeProgrammer，见 A0） | 固件、参数、脚本运行、解锁拦截、状态上报、板载日志 |
| B | A + **USB-CAN 分析仪**（支持 500k，带 120Ω 终端电阻，能循环发送指定帧） | CAN 帧格式、周期、校验，模拟 VCU 反馈，超时 / 故障 / 急停处理 |
| C | B + **双天线 RTK GPS** + 差分账号，室外 | 定位和定向、RTK 检查、**手推跑航线，检查 v/ω 的数值和正负号** |

### 0.2 要用到的文件（从 GitHub Release 下载，见 `garlic_rover/README.md`）

| 文件 | 用途 |
|---|---|
| `garlic-rover-<版本>-X-MAV-AP-H743v3.apj` | 补丁固件（MP 刷机用），下文简称 `ardurover.apj` |
| `X-MAV-AP-H743v3_bl.bin` | Bootloader（首次 DFU 刷机用，见 A0） |
| `garlic_rover.param` | 参数文件 |
| `vcu_can.lua` | Lua 脚本 |
| `CAN通信协议.md` | CAN 协议说明 |

### 0.3 SD 卡
- AP-H743v3 板上有 microSD 卡槽，卡要自备（建议 4–32 GB 的正规品牌卡）。**没有 SD 卡，脚本和日志都无法使用。**
- 卡的文件系统用 **FAT32**。新卡或来路不明的卡，先在电脑上格式化成 FAT32（32 GB 以下的卡最省事）。
- 插卡、拔卡都要在**飞控断电时**进行。

### 0.4 MP 界面总览

MP 顶部有一排大按钮，本手册用到这几个：

| 顶部按钮 | 英文 | 用途 |

| 飞行计划 | PLAN | 画航线、上传航线 |
| 初始设置 | SETUP | 刷固件、校准、可选硬件（RTK 注入） |

## 1. 基本操作（后面反复用到）

### 1.1 连接飞控
1. USB 线插上飞控和电脑，等 5 秒左右，让 Windows 识别设备。
2. MP 右上角的端口下拉框里选 **COM 口**，名字通常带 "ArduPilot" 或 "X-MAV"。如果有好几个 COM 口，拔掉 USB 看哪个消失了，就是它。
3. 波特率选 **115200**（USB 连接时其实选哪个都行）。
4. 点**连接（CONNECT）**。第一次连接会下载全部参数，进度条走完才算连上，约 10–30 秒。
5. 连上后，"连接"按钮变成"断开"，飞行数据页的仪表开始动。

### 1.2 重启飞控
最简单的办法：点"断开" → **拔掉 USB，等 3 秒再插上** → 重新连接。
只要飞控只靠 USB 供电，拔插 USB 就等于断电重启。

### 1.3 看车端消息
飞行数据页 → 左下方的标签页 → **消息（Messages）**。飞控发来的所有文字消息都在这里，最新的在最上面。
另外，解锁失败的原因会用红字显示在姿态仪表（HUD）的中间。

### 1.4 查找、修改单个参数
1. 配置/调试 → 左侧 **全部参数表（Full Parameter List）**。
2. 右侧的**搜索框**里输入参数名，比如 `SCR_ENABLE`，列表只剩匹配的几项。
3. 双击"值"那一格，改成新值，按回车。改过的行会变色。
4. 点右侧的**写入参数（Write Params）**。**不点这一步，修改不会真正写进飞控。**
5. 有的参数需要重启才生效（参数说明里写着 Reboot Required），改完按 1.2 重启。

### 1.5 从文件加载一整套参数
1. 配置/调试 → 全部参数表 → 右侧**加载（Load from file）** → 选 `garlic_rover.param`。
2. MP 会把文件里的值填进表格，有差异的行会变色。有的版本会先弹出一个对比窗口，确认即可。
3. 点**写入参数（Write Params）**。
4. 按 1.2 重启。
5. 重新连接后，再做一次第 1–4 步。原因是：有些参数只在别的参数生效后才会出现（例如 `SCR_ENABLE=1` 并重启后，脚本相关参数才会出现），第一次加载时写不进去。第二次加载能补上。

> 文件里以 `#` 开头的是注释，MP 会忽略。几个 `VCU_*` 参数是注释掉的，要等脚本运行后再手动设（见 A4）。

### 1.6 MAVLink 检查器（看原始消息）
在飞行数据页按 **Ctrl+F**，会弹出一个工具窗口，点里面的 **MAVLink Inspector**。窗口里按"飞控 → 组件 → 消息名"分组，点开某个消息就能看到它的字段值和刷新频率。

## A 级：只有飞控和 USB

> 台架上只用 USB 供电即可（A、B 级）。装车后飞控由电源口供电，**输入电压 6–35 V（2–8S）**：底盘电压超过 35 V 时必须加 DC-DC 降压模块。

### A0 首次刷机：先刷 Bootloader（只做一次）
板子出厂时可能没有 ArduPilot（比如预装的是 Betaflight），这时 MP 无法直接刷固件，要先用 DFU 方式刷入 ArduPilot 的 Bootloader。

**先判断要不要做这一步**：直接用 USB 插上飞控（不按任何键）：
- Windows 设备管理器"端口（COM 和 LPT）"下出现新 COM 口，MP 能连上并显示 ArduRover 或 ArduPilot 字样 → **已有 ArduPilot，跳过 A0，直接做 A1**；
- 没有 COM 口、MP 连不上，或显示的是 Betaflight / INAV → 做下面的步骤。

**步骤**：
1. 电脑上安装 **STM32CubeProgrammer**（ST 官网免费下载，需要注册 ST 账号）。安装时会一并装好 DFU 驱动。
2. 拔掉飞控 USB。**按住板上的 BOOT 按键不放**，插上 USB，1–2 秒后松开。此时飞控进入 DFU 模式，LED 一般不亮或常亮，属于正常。
3. 打开 STM32CubeProgrammer，右上角连接方式选 **USB**，点刷新图标，端口里应出现 `USB1`（设备管理器里显示为 "STM32 BOOTLOADER"），点 **Connect**。
4. 左侧点 **Erasing & Programming**（下载图标）：
   - File path 选 `X-MAV-AP-H743v3_bl.bin`；
   - Start address 填 **0x08000000**；
   - 勾选 "Verify programming"；
   - 点 **Start Programming**，提示成功即可。
5. 点 **Disconnect**，拔掉 USB，再**正常插上**（不按 BOOT 键）。设备管理器里应出现新的 COM 口，这就是 ArduPilot 的 Bootloader 在等固件。继续做 A1。

> 注意：刷 Bootloader 用 `.bin` 文件。ArduPilot 官方说明提示 dfu-util 不能解析 `.hex`，统一用 `.bin` 最稳妥。

### A1 刷补丁固件
1. **先断开连接**（刷固件时 MP 不能处于连接状态）。
2. 初始设置 → 左侧 **安装固件（Install Firmware）**。
3. **不要点页面中间的车型图片**（比如 Rover 小车图），点了会下载**官方固件**直接刷进去，补丁就没了。
4. 点页面右下角的**加载自定义固件（Load custom firmware）**，选 `ardurover.apj`。
5. 按提示操作：一般会让你**拔掉 USB 再插上**，然后自动开始刷写，进度条走完提示成功。
6. 按 1.1 重新连接。
7. **预期**：消息标签里能看到 `ArduRover V4.7.1 (dbe79216)` 和 `X-MAV-AP-H743v3` 字样。
8. 如果 MP 提示"板号不匹配（board id mismatch）"，说明选错了固件文件：本板的板号是 1220，只能用 Release 里文件名带 `X-MAV-AP-H743v3` 的 `.apj`，Pixhawk 6C 的固件刷不进去。

> 官方稳定版（4.7.1）里没有这块板子，我们的固件是在 4.7.1 基础上移植了板级定义后编译的，所以在 MP 里点车型图片也下载不到合适的固件。

> 补丁版和官方版的版本号完全一样，要到 A3 看脚本的提示才能区分。以后 MP 提示"有新固件"，一律不要点。

### A2 加速度计校准
Rover 不校准加速度计就解不了锁。罗盘已经在参数里关掉了，不用校准。
1. 初始设置 → **必要硬件（Mandatory Hardware）** → **加速度计校准（Accel Calibration）**。
2. 点**校准加速度计（Calibrate Accel）**，按屏幕提示依次摆 6 个姿态：水平、左侧朝下、右侧朝下、机头朝下、机头朝上、底面朝上。每摆好一个，放稳后点一次按钮（或按任意键）。
3. 全部完成后提示成功。
4. 再把飞控水平放好，点**校准水平（Calibrate Level）**。
5. 装到车上后，按实际安装方向重新校准一次水平。
6. 飞控板上的箭头要朝向车头。如果只能旋转安装，在全部参数表里把 `AHRS_ORIENTATION` 设成对应的旋转值（例如箭头朝车尾选 Yaw180），再重新做加速度计校准。

### A3 导入参数并确认"脚本功能已开启"
1. 按 1.5 加载 `garlic_rover.param`，写入，重启，然后**再加载、写入、重启一次**。
2. 在全部参数表里逐个搜索，确认：

| 参数 | 应为 | 含义 |
|---|---|---|
| `SCR_ENABLE` | 1 | 开启 Lua 脚本 |
| `CAN_P2_DRIVER` | 2 | CAN2 口使用 2 号驱动 |
| `CAN_D2_PROTOCOL` | 10 | 2 号驱动用"脚本协议" |
| `CAN_P2_BITRATE` | 500000 | CAN2 波特率 |
| `BRD_SAFETY_DEFLT` | 0 | 不需要按安全开关 |

### A4 上传 Lua 脚本

**先弄清楚 `APM/scripts` 文件夹从哪来**：这个文件夹不是本来就有的。只有满足下面两个条件，飞控上电时才会在 SD 卡上自动创建它：
1. `SCR_ENABLE=1`，并且已经重启过；
2. 插着 SD 卡。

所以一定要先完成 A3。

**方法一：MP 的 MAVFtp（不用拔卡）**
1. 配置/调试 → 左侧 **MAVFtp**。有的版本在左侧列表很靠下，要往下滚。
2. 左边是飞控上的文件夹树，一般能看到：
   - `APM`：SD 卡上的目录，里面有 `LOGS`，以及 `scripts`（满足上面两个条件后才有）；
   - `@ROMFS`、`@SYS`、`@PARAM`：固件内置的虚拟目录，**不要往里面放文件**。
3. 情况对照：

| 看到的情况 | 原因与处理 |
|---|---|
| 有 `APM`，里面有 `scripts` | 正常，继续第 4 步 |
| 有 `APM`，但没有 `scripts` | `SCR_ENABLE` 不是 1 或还没重启。确认后重启再看；也可以在 `APM` 上右键 → 新建文件夹（New Folder），手动建一个 `scripts`，注意全小写 |
| 连 `APM` 都没有 | **没插 SD 卡、卡没插好或卡格式不对**。断电后检查 SD 卡，必要时格式化成 FAT32 |

4. 点选 `APM/scripts` 文件夹 → 在右侧空白处（或文件夹上）**右键 → 上传（Upload）** → 选 `vcu_can.lua`。
5. 上传完成后，`scripts` 里应能看到 `vcu_can.lua`，大小约 10 KB。
6. 按 1.2 重启。

**方法二：读卡器（MAVFtp 用不了时）**
1. 飞控断电，拔出 microSD 卡，用读卡器插到电脑上。
2. 打开卡的根目录，应该有 `APM` 文件夹。进去，没有 `scripts` 就新建一个，名字全小写。
3. 把 `vcu_can.lua` 复制到 `APM/scripts/` 里。最终路径是 `卡根目录/APM/scripts/vcu_can.lua`。
4. 安全弹出读卡器，把卡插回飞控，上电。

### A5 确认脚本在运行
1. 重启并连接后，看消息标签。
2. **预期**：出现 `VCU: CAN bridge loaded`，说明**补丁固件和脚本都正常**。
3. 异常对照：

| 消息 | 原因 | 处理 |
|---|---|---|
| `VCU: fw lacks get_desired binding, flash patched fw` | 刷的是官方固件 | 按 A1 重刷补丁固件 |
| `VCU: no scripting CAN, check ...` | CAN 参数没生效 | 查 A3 表中的 CAN 参数，改好后重启 |
| `Lua: ...` 或 `Scripting: ...` 开头的报错 | 脚本出错或内存不足 | 记下完整原文发给我 |
| 什么相关消息都没有 | 脚本没被加载 | 查 `SCR_ENABLE=1`、脚本路径和文件名（必须是 `APM/scripts/vcu_can.lua`，扩展名是 `.lua`，不能是 `.lua.txt`） |

4. 脚本运行后，按 1.4 把参数列表刷新一下：全部参数表右侧点 **刷新参数（Refresh Params）**。
5. **预期**：搜索 `VCU_` 能看到下表这些参数，值为默认值。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `VCU_ENABLE` | 1 | 启用 CAN 桥接 |
| `VCU_FB_TMO` | 200 | VCU 反馈超时（毫秒） |
| `VCU_V_MAX` | 1.5 | 线速度限幅（m/s） |
| `VCU_W_MAX` | 1.0 | 角速度限幅（rad/s） |
| `VCU_REV` | 0 | 是否允许倒车 |
| `VCU_RTK_REQ` | 2 | RTK 要求：2 = 只接受固定解 |
| `VCU_RTK_TMO` | 3000 | RTK 掉解多久后停车（毫秒） |

### A6 解锁拦截
1. 飞行数据页 → 左下 **动作（Actions）** 标签 → 点 **解锁/上锁（Arm/Disarm）**。
2. **预期**：解锁被拒绝。HUD 上和消息标签里能看到 `PreArm: VCU: feedback timeout`，意思是没有收到 VCU 反馈，所以不允许解锁。**这是正确行为。**
3. 同时还会看到 GPS、EKF 相关的解锁失败提示（没接 GPS），也是正常现象。

### A7 查看脚本上报的状态
脚本每秒向地面站发 5 次状态，名字都以 `VCU_` 开头。有两种看法：

- **方法一（直观）**：飞行数据页 → 左下 **快速（Quick）** 标签 → 双击任意一个数值格子 → 在弹出的列表里找 `MAV_VCU_OK`、`MAV_VCU_MODE` 等，勾选后显示在格子里。不同 MP 版本的前缀可能不同，在列表里搜 `VCU` 即可。
- **方法二**：按 1.6 打开 MAVLink Inspector → 找 `NAMED_VALUE_FLOAT`。这个消息轮流携带 9 个名字的值，展开后能看到 `name` 和 `value` 在变。

**预期**（没接 VCU 时）：
- `VCU_OK = 0`（底盘未就绪）；
- `VCU_MODE = -1`（还没收到过 VCU 状态）；
- `VCU_CMD_V`、`VCU_CMD_W` = 0（没有下发运动指令）。

### A8 板载日志
脚本会往飞控日志里写一个名为 `VCU` 的记录（每秒 50 条）。飞控默认只在解锁后记日志，台架上解不了锁，所以要临时打开"未解锁也记录"。

1. 按 1.4 把 `LOG_DISARMED` 设为 1，写入，重启，等 1 分钟。
2. 飞行数据页 → 左下 **数据闪存日志（DataFlash Logs）** 标签 → **通过 MAVLink 下载闪存日志（Download DataFlash Log Via Mavlink）** → 勾选**编号最大**（最新）的一个 → 下载。日志存在"我的文档\Mission Planner\logs\"下，扩展名是 `.bin`。
3. 同一个标签页点 **回顾日志（Review a Log）** → 选刚下载的 `.bin`。
4. 在打开的窗口左侧列表里找 `VCU`，展开后勾选 `CV`、`CW` 等字段，右侧会画出曲线。
5. **预期**：有 `VCU` 这一项，包含 `CV, CW, V, W, Str, Md, Flt, Ok, Fix` 共 9 个字段，`CV`、`CW` 恒为 0。
6. **测完把 `LOG_DISARMED` 改回 0。**

## B 级：加 USB-CAN 分析仪

### B0 分析仪接线与设置
1. **接线**：分析仪接飞控上标 **CAN2** 的接口，**只接 CAN_H、CAN_L、GND 三根**，**5V 那根不接**。
   - 接口位置和针脚顺序以板子底面丝印为准，也可以对照 ArduPilot 源码里该板目录下的接线图 `AP-H743v3_BottomPort.png`（`libraries/AP_HAL_ChibiOS/hwdef/X-MAV-AP-H743v3/`）。
   - 不同厂家的针脚顺序不一样，**不要照搬 Pixhawk 的顺序**，接之前用万用表确认 GND。
2. **打开分析仪的 120Ω 终端电阻**。一般是拨码开关或软件里的选项。台架上只有飞控和分析仪两个节点，不开的话会有大量错误帧，甚至收不到数据。
3. **分析仪软件设置**（周立功 CANTest、CANable 配套软件等都类似）：
   - 波特率 **500 kbit/s**；
   - 工作模式选"**正常模式**"。不要选"只听模式"，否则分析仪不回应答（ACK），飞控会一直报发送错误。
   - 帧类型：**标准帧**、**数据帧**。
4. 飞控用 USB 供电并连上 MP，分析仪软件点"打开/启动"。

### B1 检查飞控发出的指令帧
1. 在分析仪软件的接收窗口观察。
2. **预期**：
   - 能收到 ID 为 **`0x101`**（有的软件显示为 `101` 或 `00000101`）的帧，长度（DLC）为 8，每秒约 50 帧（间隔 20 ms）；
   - 未解锁时数据形如 `00 00 00 00 00 00 0C 0C`：
     - 第 1–4 字节是 v 和 ω，都为 0；
     - 第 5 字节是标志位，为 0，表示"自动使能"关闭；
     - 第 7 字节是计数器，在 00–0F 之间逐帧加 1，到 0F 后回到 00；
     - 第 8 字节是校验。此时前 7 字节只有计数器不为 0，所以校验恰好等于计数器。
3. 连续观察 1 分钟，计数器不跳号、帧间隔稳定，就算通过。

### B2 用分析仪假扮 VCU（正常就绪）
在分析仪软件里设置"**定时 / 循环发送**"，同时循环发下面两帧，都用标准帧、数据帧、DLC 8：

| ID | 周期 | 数据 | 含义 |
|---|---|---|---|
| `201` | 20 ms | `F4 01 00 00 00 00 00 F5` | 实际车速 0.5 m/s，其余为 0 |
| `202` | 100 ms | `02 00 00 00 00 00 00 02` | VCU 处于自动模式，无故障 |

**预期**：
1. 按 A7 的方法看，`VCU_MODE` 变成 **2**，`VCU_V` 变成 **0.5**。
2. 再点解锁：提示从 `VCU: feedback timeout` 变成 **`VCU: no RTK fix`**。这说明 VCU 检查已通过，现在卡在 RTK 检查（没接 GPS），同样是正确行为。
3. 临时把 `VCU_RTK_REQ` 设为 **0**（关闭 RTK 检查），`VCU_OK` 会变成 **1**，VCU 相关的解锁提示消失。

### B3 反馈超时
1. 保持 B2 的状态，**停止发送 `201`**，`202` 继续发。
2. **预期**：0.2 秒内 `VCU_OK` 变回 0，解锁提示变回 `VCU: feedback timeout`。
3. 恢复发送 `201`，再**只停止 `202`**，预期约 0.5 秒内出现同样结果。

### B4 VCU 状态异常
保持 `201` 正常发送，依次把 `202` 的数据改成下表，每次改完点一下解锁看提示：

| `202` 数据 | 模拟情况 | 预期解锁提示 |
|---|---|---|
| `00 00 00 00 00 00 00 00` | VCU 在手动模式 | `VCU: not in auto` |
| `02 01 00 00 00 00 00 03` | VCU 急停 | `VCU: estop` |
| `02 02 12 00 00 00 00 12` | 故障，故障码 0x0012 | `VCU: fault 0x0012` |
| `02 00 00 00 00 00 00 00` | **校验错误**（最后一字节应为 02） | 这帧被丢弃，约 0.5 秒后出现 `VCU: feedback timeout` |

> 校验规则：第 8 字节 = 前 7 字节逐个异或。自己编测试数据时可以用 Windows 计算器的"程序员"模式算 XOR。

### B5 拔插与终端电阻
1. 飞控运行中**拔掉 CAN 线**，等几秒再插回。
   - **预期**：拔掉期间报反馈超时；插回后自动恢复，脚本不报错，不需要重启。
2. 关掉分析仪的终端电阻，观察接收情况。
   - 预期会出现错误帧或收不到数据。这一步是为了让你亲眼确认：正式接 VCU 时，终端电阻一定要配好。

## C 级：加 RTK GPS（室外，不需要底盘）

### C0 GPS 配置
0. **接线**：RTK GPS（如 UM982）接飞控上标 **GPS** 的串口，即 SERIAL3（USART1），TX/RX 交叉连接。GPS 模块的供电按其规格接（一般 5 V，板上有 5 V BEC），室外测试时建议用电池给飞控供电，不要只靠 USB。
1. 按实际型号设参数，写入并重启：
   - UM982：`GPS1_TYPE = 25`；
   - 两台 F9P 做移动基线：`GPS1_TYPE = 17`，`GPS2_TYPE = 18`。
2. 测量天线相对飞控的位置（单位米，前、右、下为正），填到 `GPS1_POS_X / Y / Z`。两台 F9P 还要填 `GPS2_POS_*`。双天线定向对这几个值比较敏感，要量准。
3. 参数文件里已经设好 `EK3_SRC1_YAW = 2`（航向用 GPS），不用再改。

### C1 定位、定向与差分注入
1. 到空旷的室外，天线朝天，等 2–5 分钟。
2. **差分注入**（地面站转发方式）：初始设置 → **可选硬件（Optional Hardware）** → **RTK/GPS Inject**：
   - 左上下拉框选 **NTRIP**，点 **连接（Connect）**；
   - 弹窗里按格式填写 `ntrip://用户名:密码@服务器地址:端口/挂载点`；
   - 连上后页面显示收发字节数，字节数一直在增加才说明差分数据在流动。
3. **预期**：
   - 飞行数据页 HUD 上的 GPS 状态依次变为 `3D Fix` → `RTK Float` → **`RTK Fixed`**；
   - 双天线定向正常：把整套设备原地转 90°，地图上的航向也转 90°，靠近铁件时航向不跳。

### C2 RTK 检查
1. 把 `VCU_RTK_REQ` 改回 **2**，分析仪继续按 B2 发送。
2. **预期**：
   - 固定解之前不能解锁，提示 `VCU: no RTK fix`；
   - 拿到固定解（RTK Fixed）后，VCU 和 RTK 相关的解锁提示都消失。

### C3 手推跑航线，检查 v/ω（最关键）
把飞控、GPS、电池（或充电宝供电）、电脑（或数传）和分析仪装在手推车上，或由人拿着，模拟车辆行驶。

1. **画航线**：飞行计划页（PLAN）：
   - 在地图上**左键单击**添加航点，画"直行 20 m → 左转 → 直行 10 m → 右转 → 直行 10 m"；
   - 右侧点 **写入航点（Write WPs）** 上传到飞控；
   - 点 **读取航点（Read WPs）**，确认读回来的和画的一样。
2. **准备**：
   - 分析仪按 B2 持续发送模拟 VCU 帧；
   - 临时把 `FS_CRASH_CHECK` 设为 **0**。推得慢时，飞控会以为车陷住了而停车，这项检查属于实车保护，手推测试时先关掉。
3. **开始**：
   - 飞行数据页 → 动作标签 → 点解锁；
   - 动作标签里的模式下拉框选 **Auto** → 点 **设置模式（Set Mode）**；
   - 然后推着车沿航线走，速度约 0.5–1 m/s（正常步行偏慢）。
4. **预期**（看分析仪收到的 `101` 帧，也可以看 A7 的 `VCU_CMD_V / W`）：
   - 第 5 字节变成 `01`，表示自动使能；
   - 直行时 v ≈ `WP_SPEED`：0.8 m/s 对应第 1–2 字节为 `20 03`（0x0320 = 800），ω 接近 0；
   - **航线向左转时 ω 为正，向右转时 ω 为负**。ω 在第 3–4 字节，负数的第 4 字节会是 `FF` 左右。**这是正负号的最终确认。**
   - 故意偏离航线往右走，ω 应为正，表示指令车头向左纠偏；
   - 模式切到 **Hold**，v、ω 立即变 0，第 5 字节变 `00`。
5. **看日志**：按 A8 下载本次日志，同时勾选 `VCU.CV` 与 `THR.DesSpeed`，二者应重合；再对比 `VCU.CW` 与 `STER.DesTurnRate`：
   - 正负号相反：ArduPilot 右转为正，我们发给 VCU 的是左转为正；
   - 单位不同：`CW` 是 rad/s，`DesTurnRate` 是 deg/s，数值差约 57.3 倍。

### C4 行驶中的保护
在 C3 推行过程中逐项制造异常，每项测完恢复正常，再切 Auto 继续：

| 操作 | 预期 |
|---|---|
| 分析仪停发 `201` | 0.2 秒内切 Hold，消息 `VCU: feedback timeout, HOLD` |
| `202` 改成手动模式（`00 ... 00`） | 切 Hold，消息 `VCU: not in auto, HOLD` |
| 用手或金属板遮住天线，或断开 NTRIP，失去固定解超过 3 秒 | 切 Hold，消息 `VCU: RTK lost, HOLD` |
| 断开 MP 连接（点"断开"或拔数传）超过 5 秒 | **继续按航线走**，消息 `GCS Failsafe` 和 `Failsafe - Continuing Auto Mode`（`FS_GCS_ENABLE=2`，与地面站断线提示一致）。再切到 Hold 后断开，5 秒后保持 Hold |

## 常见问题

| 问题 | 原因 / 处理 |
|---|---|
| 首次插上 USB 没有 COM 口 / MP 连不上 | 板子可能还没有 ArduPilot，按 A0 用 DFU 刷 Bootloader |
| STM32CubeProgrammer 里找不到 USB1 | 没进 DFU：拔掉 USB，**按住 BOOT 键再插**；或者 DFU 驱动没装好，重装 STM32CubeProgrammer |
| MP 刷固件提示板号不匹配 | 选错了固件文件，见 A1 第 8 步 |
| MP 端口列表里没有 COM 口 | 换一根**能传数据**的 USB 线（有的线只能充电）；或者到 Windows 设备管理器里看是否识别了设备 |
| 连接时卡在"获取参数" | 断开，拔插 USB 后重连；也可以换一个 USB 口 |
| MAVFtp 里没有 `APM/scripts` | 见 A4：先 `SCR_ENABLE=1` 并重启，还要确认插着 SD 卡 |
| MAVFtp 里连 `APM` 都没有 | SD 卡没插、没插好或格式不对，断电后检查并格式化成 FAT32 |
| 脚本上传了但没有 `VCU: CAN bridge loaded` | 见 A5 异常对照表 |
| 看不到 `VCU_*` 参数 | 脚本没运行（先解决 A5）；或者参数表没刷新，点"刷新参数" |
| 分析仪收不到 `101` | 接的不是 CAN2 口；波特率不是 500k；终端电阻没开；分析仪在"只听模式"；CAN_H 和 CAN_L 接反了 |
| 解锁一直失败 | 看 HUD 红字和消息标签里 `PreArm:` 后面的原因，对照本手册处理，或把原文发给我 |
